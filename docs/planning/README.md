# Dili Salon Management & Analytics System

Архитектура және іске асыру жоспары. Жаңартылған күні: **2026-11-13**. Мәртебесі: **P1 шолуынан кейін нақтыланған техникалық жоба; іске асыру басталған жоқ**.

## Негізгі бағыт

Алдымен күнделікті операцияларды толық әрі дәл тіркейтін жүйе құрамыз. Аналитиканың сенімділігі осы деректерге тәуелді. Қолданыстағы Excel файлы расталған бастапқы дерек ретінде қабылданбайды.

Ұсыныс: Next.js ішіндегі модульдерге бөлінген бір қолданба, Supabase Auth, PostgreSQL және RLS. Қызмет фактілері, клиент төлемдері, шығындар және қызметкерге есептелген табыс жеке ұғымдар болады. Ақша операциялары транзакциямен жазылады; қателер бастапқы жазбаны жою арқылы емес, себеп көрсетілген түзетумен жөнделеді.

Құжаттар `mukhamedzhankubantov/dili-salon-management` Git репозиторийінің `docs/planning/` бумасында нұсқаланады. Бастапқы құжаттар `6b4634a` commit-інде сақталған. Бұл кезеңде тек жоспарлау құжаттары өзгереді: қолданба коды, SQL миграциялары, тәуелділіктер және сыртқы ресурстар жасалмайды. Мысалдардың бәрі жасанды; нақты клиент, қызметкер аккаунты немесе қаржылық операция деректері Git-ке енгізілмейді.

## Бекітілген техникалық шешімдер

1. Бір салон, KZT, модульдік монолит; қызмет пен төлем бөлек.
2. Комиссия ережесінің болмауы орындалған қызметті сақтауды тоқтатпайды. Комиссия `pending`, расталған нөлмен тең емес.
3. `effective_at`/`effective_business_date`, `created_at` және `correction_commands.corrected_at` бөлек мағынаға ие. Тарихи түзету бүгінгі жалған ақша қозғалысын жасамайды.
4. Employee өз қызметін тіркей алады; бақыланатын `visit_participants` арқылы бірнеше маман бір келуге қатыса алады. Ортақ келу басқа маманның құпия сомаларын ашпайды.
5. Қызметкер–аккаунт байланысын тек Owner арнайы аудиттелетін командамен басқарады.
6. Қызметкерлер күн соңында өз қызметтерін тексереді; ақша салыстыруын уәкілетті жауапты адам атқарады. Бұл екі бөлек бақылау.
7. Бастапқы фактілер, correction, reversal және аудит сақталады. Кеш енгізуге себеп және тиісті рұқсат қажет.
8. Шешілмеген төлемдер, толықтырылмаған келулер, duplicate candidates және pending commissions көрінеді; қалыпты аноним келу қате болып саналмайды.

Бұл шешімдер жүйенің талаптары ретінде бекітілді. Қызметкерді ортақ келуге кім қосатыны, кім кассир болатыны, комиссия формуласы, тексеру мерзімі және айырмашылықты бекіту тәртібі — әлі расталмаған салон рәсімдері. Олардың тізілімі: [06-business-assumptions.md](06-business-assumptions.md). Техникалық нұсқа үшін ұсынылған қауіпсіз әдепкі рұқсаттар салонның қазіргі тәжірибесі туралы факт емес.

## Алдымен келісілетін шешімдер

1. Қызметті кім тіркейді, ал төлемді кім растайды?
2. Қызметкер табысы қызмет бағасынан ба, жеңілдіктен кейінгі сомадан ба, әлде нақты түскен ақшадан ба есептеледі?
3. Қарыз, аванс, қайтарым, сыйақы және бірнеше орындаушы қалай өңделеді?
4. Күнді кім жабады, ал жабылған күнге қатысты қатені кім түзетеді?
5. Дербес деректерді, Auth деректерін, журналдар мен сақтық көшірмелерді қайда сақтаймыз?

Қазақстандағы сақтау және трансшекаралық беру талаптары орналастыру шешіміне әсер етеді. Ресми Supabase аймақтарының тексерілген тізімінде Қазақстан көрсетілмеген. Сондықтан Supabase Cloud + Vercel production конфигурациясы әзірге шартты ұсыныс; нақты деректерді енгізер алдында орналастырудың жарамдылығы анықталуы тиіс. Негіздеме: [қауіпсіздік құжаты](04-permissions-security.md#дербес-деректер-және-орналастыру).
